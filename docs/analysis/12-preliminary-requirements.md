## 六、系统架构需求

### 6.1 架构改进

| 编号 | 需求 | V2痛点 | 改进方向 |
|------|------|--------|----------|
| ARCH-001 | **去除Electron壳** | O17003作为REST API却包在Electron桌面壳中 | **必须：** 后端服务使用纯Node.js/Docker部署 |
| ARCH-002 | **统一代码库** | 6+个几乎相同的代码库(FDY/DTY/纺纱各复制一份) | **必须：** 单一代码库+产品线配置化 |
| ARCH-003 | **统一数据库** | h028/h030/fangsi三个独立数据库 | **必须：** 单库多租户/多产品线 |
| ARCH-004 | **API文档** | 280+端点无文档 | **必须：** OpenAPI/Swagger自动生成 |
| ARCH-005 | **自动化测试** | 零测试覆盖 | **必须：** 单元测试+集成测试+E2E测试 |
| ARCH-006 | **数据库迁移** | 无migration工具 | **必须：** 引入Knex/Prisma/TypeORM等迁移工具 |
| ARCH-007 | **多实例合并** | O17007有6个目录各跑一个实例 | 单服务多配置实例（K8s或PM2） |

### 6.2 安全性

| 编号 | 需求 | V2痛点 | 改进方向 |
|------|------|--------|----------|
| SEC-001 | **修复SQL注入** | `dailyBobbinsAmounts.js`直接拼接SQL | **P0必修：** 参数化查询 |
| SEC-002 | **启用认证中间件** | JWT+RBAC已实现但几乎所有路由未应用 | **必须：** 全局认证中间件 |
| SEC-003 | **安全密码哈希** | 使用MD5哈希密码 | **必须：** 改用bcrypt/argon2 |
| SEC-004 | **凭据管理** | 数据库密码硬编码在config.js | **必须：** 环境变量或密钥管理服务 |
| SEC-005 | **HTTPS** | 全部HTTP明文通信 | **建议：** 内网TLS或VPN隧道 |

### 6.3 性能与可靠性

| 编号 | 需求 | V2痛点 | 改进方向 |

## 八、混合生产支持（新增需求域）

> 基于V2架构分析，当前系统无法支持混合生产线。以下为支持混合生产需要新增的核心需求。

| 编号 | 需求 | 说明 |
|------|------|------|
| MIX-001 | **统一纱锭数据模型** | 设计一个能承载FDY(doffing关联)和DTY(module直接关联)两种追踪模式的通用模型 |
| MIX-002 | **产品线配置引擎** | 按产品线配置：模组位数、等级体系、追踪路径、工艺流程 |
| MIX-003 | **生产流程策略模式** | 落纱/装载/分拣等核心操作通过策略模式按产品类型分派，而非代码分支 |
| MIX-004 | **混合线调度** | 同一物理产线可切换生产不同产品类型，调度器需感知当前产品模式 |
| MIX-005 | **统一存储过程** | 将`manage_doffing`和`manage_dty_bobbins`抽象为统一的"纱锭装载"过程 |
| MIX-006 | **跨产品线追溯** | POY→DTY的全链路追溯（POY原丝到DTY成品的质量关联） |
